# Execution gaps review — September 16, 2026

This pass adds fifteen lessons inside the existing parallel-training, inference,
serving and frontier chapters. It addresses a recurring gap: naming a technique
without showing the intermediate values, ownership transitions or measurements
needed to implement it correctly.

The four additions have independent content, numerical models, controls and
companion examples. Canonical labels and search are still generated by the
reader. The MoE execution sequence follows the existing MoE introduction. New
scheduling and measurement lessons precede prefill/decode disaggregation.

## Original numerical examples

### Sharding and live memory

The declared four-group memory model has 134,217,728 parameters. On four ranks,
FP32 original parameter shards and two Adam moment shards occupy 384 MiB. Its
default live peak is 704 MiB after adding gathered compute weights, a full
gradient and saved activations. One-group prefetch raises it to 768 MiB;
retaining gathered weights raises it to 896 MiB. These are explicitly ordered
tensor-payload calculations, not allocator or FSDP telemetry.

The CPU reference trains a four-coordinate linear model with uneven data
partitions. It checks five AdamW updates against an unsharded reference, both
moments and the bias-correction step. It saves after two updates, serializes
logical chunks, restores with four owners instead of two and continues. Missing,
overlapping or inconsistent chunks are rejected. A separate test counts actual
small FP32/16-bit array payloads without pretending to execute BF16 arithmetic.

### Quantization

The scalar quantizer states nearest/ties-to-even rounding **before** adding the
integer zero point. Grouped matrices use `W[output,input]`, groups along input
channels and the symmetric narrow signed range. The most-negative two's-complement
code is unused. Tail groups and an all-zero-group convention are explicit.

The Python reference packs a real four-byte INT4 payload, with the earlier code
in the low nibble, while keeping shape/group/scale metadata separate. A complete
enumeration of the 225 legal two-code pairs tests packing and unpacking. A small
counterexample has lower weight MSE but nine times greater squared output error.
The browser makes input-distribution and channel-transform effects inspectable.

### Mixture of experts

Four token rows, two channels and three linear experts keep every value visible.
Top-2 selected-softmax routing produces expert loads `[2,4,2]`. Packed token IDs
are `[0,3,0,1,2,3,1,2]`; the repeated IDs are separate expert assignments. Weighted
inverse combination reconstructs the outputs, while all 24 input permutations
preserve them after restoring row order.

Capacity two drops two assignments to expert 1. Keeping original gates and
renormalizing survivors give different outputs; neither equals the dropless
function. Changing ownership can keep total remote bytes unchanged while
changing per-rank compute load. Backward tests use independently evaluated dense
expert outputs and finite differences away from top-k boundaries. Router logits
are independent inputs in the companion; the prose separately derives the
additional input/weight path for a learned linear router.

### Serving and measurement

Two requests each have four prompt positions and six outputs. With four-position
blocks, each needs three blocks at its maximum. In a four-block pool, growing
allocation lets both reach eight cached positions and five emitted outputs;
neither can allocate the block needed to finish. Reserving the output limit
serializes admission and lets both complete. Cancellation is modeled only after
previous execution completes; the model does not implement eviction or transport.

The single-server arrival model uses eight requests, a 100 ms open-loop interval
and 200 ms service. Request eight waits 700 ms and takes 900 ms end to end. A
single closed-loop client offers less work and each response takes 200 ms. Both
cohorts finish at 1,600 ms, demonstrating that equal aggregate completion rate
does not establish equal latency.

The delivery trace has four offered attempts, three successful completions and
two compliant completions in a fixed one-second window. Goodput is 2 requests/s
and attainment is 50%. Two successful streams have the same 20 ms TPOT, but worst
gaps of 20 and 80 ms. Terminal completion follows the last token; one-token
answers have no between-token metric. A partially streamed failure stays in the
offered population and does not enter compliant completions.

Actual browser reviews cover bit-width/scale/group controls, FSDP memory and
prefetch policies, update owners, MoE routing/capacity/gradients, scheduler
priority, reservation/cancellation and the delivery objective. Phone-width tables
and diagrams scroll within their own region, with visible cues and keyboard
access. Screenshots are under `output/playwright/`. The shared system inspector's
changing component title is excluded from static heading indexing, preventing
search entries that disappear after selection changes.

The sharded update and MoE programs use logical ranks in one CPU process.
Quantization checks real byte packing but executes ordinary floating arithmetic.
Serving traces are declared arithmetic and token receipts, not captured engine
traffic. These results establish no GPU kernel speed, actual collectives, model
quality, quantized-checkpoint compatibility, network transport or serving
capacity. The lessons give the comparison contracts required for those next
target-environment experiments.
